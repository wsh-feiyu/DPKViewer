# DPK（寻仙 whpackage1.0）包格式说明

本文件由参考实现 `dpk.py` 逐段复刻整理，是 DPKViewer 全部读写逻辑的唯一依据。
所有多字节整数均为 **小端序（little-endian）**，偏移量以字节为单位。

---

## 1. 整体结构

```
DPK 文件 = N 个 1024 字节的「块」(block)，块号从 0 开始

块 0            包头
块 1..N-1       由包头引用的若干条「虚拟文件」块链，以及各文件自身的块链
```

常量：

| 名称 | 值 |
| --- | --- |
| 块大小 `BLOCK` | 1024 |
| 包魔数 | `whpackage1.0`（12 字节，位于块 0 偏移 0） |
| 流魔数 | `whsc1.0`（7 字节，位于虚拟文件内容偏移 0） |
| PackagePassword | `tianxiawudi` |
| ContentPassword | `gandiaosifu` |

---

## 2. 块 0：包头

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0x00 | 12 | 魔数 `whpackage1.0` |
| 0x20 | 16 | `MD5("tianxiawudi")`，包口令标记 |
| 0x84 | 4 | 目录树虚拟文件的根块号 |
| 0x88 | 4 | 路径名表虚拟文件的根块号 |

其余字节在读取路径中未被使用。生成新包时，除上述字段外的字节**写入 0**；也可以选择「沿用模板包头」，即整块复制某个已存在的 DPK 的块 0，仅改写 0x84 / 0x88，用于最大程度保持与原包头部一致。

---

## 3. 虚拟文件（块链）

每个虚拟文件占用一条块链，链上每个块 1024 字节。

### 3.1 根块（链首块）

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | `prev`，必须为 0（是根块的判定条件） |
| 4 | 4 | `next`，后继块号，0 表示链结束 |
| 8 | 4 | `tail`，链尾块号（单块文件时等于自身块号） |
| 12 | 4 | `fileSize`，虚拟文件的总字节数 |
| 16 | 4 | 时间戳字段（仅就地替换时保留原值，读取不使用） |
| 20 | 12 | 保留 |
| 32 | 992 | 负载（前 992 字节） |

### 3.2 后续块

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 4 | `prev`，前驱块号，必须等于链表中的上一块 |
| 4 | 4 | `next`，后继块号，0 表示链结束 |
| 8 | 1016 | 负载（1016 字节） |

### 3.3 读取算法（与 dpk.py `_vfile` 一致）

1. 读根块，要求 `prev == 0`；
2. 取根块负载 `root[32 : 32 + min(fileSize, 992)]`；
3. 沿 `next` 行进，要求每个后续块的 `prev` 等于上一块号，每块最多再取 `min(剩余, 1016)` 字节；
4. 出现重复块号（成环）、`prev` 不匹配、或走完后当前块号 ≠ `tail`，均判定为损坏。

### 3.4 容量公式（与 dpk.py `blocks_for` 一致）

```
size <= 992            -> 1 块
否则                    1 + ceil((size - 992) / 1016) 块
```

单块可用容量 992 字节，之后每块增 1016 字节。

## 4. 文件内容：whsc1.0 流

虚拟文件的负载字节本身是一段 whsc 流：

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 7 | 魔数 `whsc1.0` |
| 7 | 8 | 保留 |
| 15 | 1 | `flags` |
| 16 | 16 | `MD5(明文)` |
| 32 | 4 | 保留（0） |
| 36 | 4 | `plainSize`，明文长度 |
| 40 | 4 | `storedSize`，负载长度 |
| 44 | 4 | 常量 `0x543B3338`（写入时填充，读取不使用） |
| 48 | storedSize | 负载 payload |

`flags` 位定义：

| 位 | 含义 |
| --- | --- |
| 0x01 | payload 为 zlib 压缩数据 |
| 0x02 | payload 已加密 |
| 0x04 | 加密口令使用 ContentPassword，否则使用 PackagePassword |

### 4.1 解码顺序（dpk.py `_decode_whsc`）

1. 校验长度 ≥ 48 且魔数为 `whsc1.0`；
2. `payload = data[48 : 48 + storedSize]`；
3. 若 `flags & 0x02`：口令取 `flags & 0x04 ? ContentPassword : PackagePassword`，用其**前 8 字节**作为密钥解密（§5）；
4. 若 `flags & 0x01`：对结果做 zlib 解压；
5. 校验长度 == `plainSize`，且 `MD5(结果) == data[16:32]`，任一不符即判定为损坏。

### 4.2 编码（dpk.py `encode_whsc`，flags 默认 3）

```
plain -> zlib.compress(plain, 9)
      -> 若 flags&0x02：DES 变体加密（§5）
      -> 写 48 字节头 + 负载
```

> **参考实现中的一处不一致**：`dpk.py` 的写入函数在 `flags & 0x01 == 0` 时把 `stored` 直接置为明文（即「只加密不压缩」会写出自相矛盾的流）。
> DPKViewer 的写入按语义自洽处理：`flags=2` 时负载为 `encrypt(plain)`，其长度等于明文长度；该输出可被 `dpk.py` 的**读取**函数正确解出。

## 5. DES 变体加密（DES-CBC，零 IV + 尾块混淆）

密钥 `key8` = 口令前 8 字节。设 `full = floor(len/8)*8`。

### 5.1 完整块部分

与 DES-CBC（IV 全 0）等价：

- 加密：`C_i = DES_ECB_Encrypt(P_i XOR C_{i-1})`，`C_0_prev = 0`
- 解密：`P_i = DES_ECB_Decrypt(C_i) XOR C_{i-1}`，`C_0_prev = 0`

参考实现写作 `DES.MODE_ECB`，但在结果上逐块异或前一块密文，因此实际语义为 CBC。

### 5.2 尾块（不足 8 字节，1..7 字节）

这一段的处理不是标准 CBC，需要按位复刻：

加密（明文尾 `t`，前一密文块 `C`）：

```
for i in 0..r-1:  t[i] = plain[full+i] XOR key8[i] XOR t[i-1] XOR C[i]      // t[-1] 视作 0
parity = (t[r-1] + t[0]) & 1
for left in 0..r/2-1:  right = r-1-left
    if ((t[right] + t[left]) & 1) == parity:  swap(t[left], t[right])
```

解密（密文尾 `t`，前一密文块 `C`）：

```
parity = (t[r-1] + t[0]) & 1
for left in 0..r/2-1:  right = r-1-left
    if ((t[right] + t[left]) & 1) == parity:  swap(t[left], t[right])
for i in 0..r-1:  out[i] = t[i] XOR key8[i] XOR t[i-1] XOR C[i]            // t[-1] 视作 0
```

注意：加密时的 `parity` 在异或填充**之后**、交换之前计算；解密时的 `parity` 在交换之前计算。两者取值恒等，交换条件构成互逆操作。

`key8[i]` 在尾块中按下标直接取值（不会越界，因为 `r < 8`）；`C[i]` 为前一完整块的密文，若 `full == 0` 则为全 0。

## 6. 目录结构（两块虚拟文件）

### 6.1 路径名表（names）

一个虚拟文件，内容是若干以 `0x00` 结尾的路径片段（目录名或文件名）拼接。**引用方式是按字节偏移**：记录中保存的是名字在该文件内的起始偏移。

### 6.2 目录树（tree）

一个虚拟文件，内容是字节紧凑的记录序列，解析时维护一个目录栈：

| 首字节 | 后续 | 含义 |
| --- | --- | --- |
| 1 | 2 × u32：`nameOffset`、`rootBlock` | 文件条目：路径 = 栈内目录 + 该名字 |
| 2 | u32：`nameOffset` | 进入子目录（压栈） |
| 3 | 无 | 退出当前目录（弹栈） |
| 其它 | — | 判定为损坏 |

条目路径以 `/` 连接；条目解出的 `rootBlock` 即为其内容所在块链的根块号（§3）。

## 7. 生成（打包）时的布局

DPKViewer 的写入按下列顺序线性分配块号，块 0 固定为包头：

```
块 0                        包头
各文件条目（按排序后的顺序）  每个文件一条 whsc 流块链
目录树虚拟文件               一条块链（treeRoot）
路径名表虚拟文件             一条块链（namesRoot）
```

由于目录树记录中保存的是各文件的根块号，且这些块号在写入目录树之前就已确定，因此先分配文件内容块，再构造目录树，最后构造路径名表；包头中的 0x84 / 0x88 在写完两块后回填。整个文件以 0 补齐到 1024 的整数倍。

文件顺序：按相对路径（UTF-8 字节序）排序，保证同一输入目录每次生成结果完全一致。

---

## 8. 名称的字符编码

参考实现按 ASCII 解码名称（非法字节替换为 `?`）。文件名在包内只是不参与校验的字节串，因此：

- 生成：名称优先用系统 ANSI 代码页编码，无法表示时退回 UTF-8；
- 读取：先按 UTF-8 严格解码，失败则按系统 ANSI 代码页解码，用于界面显示；
- 两种情况下条目的字节偏移结构不受影响，解包仍以包内原始路径为准。

---

## 9. 已知未确认项

- 块 0 中除 0x00 / 0x20 / 0x84 / 0x88 以外的字段含义未知：生成时置 0，或使用「沿用模板包头」保留原值。
- `flags` 的 0x04（ContentPassword）分支在读取时已实现；生成时统一使用 PackagePassword。
- 若目标程序还校验包内其它结构（例如头部保留字段），需要以真实原包为模板生成。
